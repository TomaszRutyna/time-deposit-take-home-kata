# AI Usage Documentation

## Overview

This document describes how AI tools were utilized during the development of the Time Deposit application. AI assistance was employed selectively to accelerate development of repetitive, boilerplate-heavy, or straightforward code while keeping architectural decisions and complex business logic under human control.

---

## Areas of AI Assistance

### 1. Test Generation

AI was used to generate unit and integration tests for straightforward scenarios:

- **Domain unit tests** — parameterized tests for `BasePlanDefinition` (interest calculation with various inputs) and `PlanDefinitionResolver` (plan type mapping)

AI-generated tests followed the existing project conventions (JUnit 5, AssertJ assertions, Testcontainers for integration tests) and were reviewed for correctness before inclusion.

### 2. SQL Scripts

AI assisted in generating Liquibase migration scripts:

- **Initial schema script** (`V20260806124700-initial-script.sql`) — DDL for `time_deposits` and `withdrawals` tables based on the domain model requirements
- **ShedLock table script** (`V20260806224700-shedlock.sql`) — standard ShedLock schema for distributed scheduler locking

These scripts were generated based on entity definitions and reviewed for data type accuracy, constraint correctness, and indexing.

### 3. Code Review

AI was used as a code review assistant for:

- **Identifying code smells** — detecting long methods, unclear naming, and unnecessary coupling
- **Suggesting refactoring opportunities** — improving readability and maintainability
- **Verifying hexagonal architecture adherence** — ensuring domain layer remains free of framework dependencies
- **Reviewing error handling** — checking for missing edge cases and proper exception propagation

### 4. Removing Code Smells

Based on AI-assisted code review findings, the following improvements were made:

- Extracting complex logic into well-named private methods
- Reducing method length by splitting responsibilities
- Improving variable and method naming for clarity
- Removing dead code and unused imports
- Simplifying conditional logic

### 5. Code Snippet Generation (Mappers)

AI generated boilerplate mapper code that transforms objects between architectural layers:

- **REST mappers** — converting between OpenAPI-generated DTOs (`TimeDepositRequest`, `TimeDepositResponse`) and domain models (`TimeDeposit`, `Withdrawal`)
- **Persistence mappers** — converting between JPA entities (`TimeDepositEntity`, `WithdrawalEntity`) and domain models

These mappers are simple field-to-field transformations that are tedious to write manually but straightforward enough to generate reliably.

---

## AI Usage Principles

The following principles guided AI tool usage in this project:

| Principle | Description |
|-----------|-------------|
| **Human-driven architecture** | All architectural decisions (hexagonal structure, port/adapter boundaries, domain modeling) were made by the developer |
| **AI for boilerplate** | AI was used primarily for repetitive, low-risk code that follows established patterns |
| **Review everything** | All AI-generated code was reviewed, tested, and adjusted before integration |
| **Domain logic by hand** | Core business logic (interest calculation rules, withdrawal detection, scheduling) was written and verified manually |
| **Consistency** | AI was instructed to follow existing project conventions (naming, structure, testing patterns) |

## Tools Used

- **AI Code Assistant** — used within the IDE for code generation, review, and refactoring suggestions
- **Chat-based AI** — used for discussing architectural approaches and verifying business logic interpretation

## What Was NOT Generated by AI

The following critical parts of the application were developed without AI generation:

- Hexagonal architecture design and package structure
- Domain model design (`TimeDeposit`, `Withdrawal`, plan types)
- Business rules implementation (`TimeDepositCalculator`, `BasePlanDefinition`)
- OpenAPI specification design
- Application configuration structure
- Spring Boot wiring and dependency injection setup
- Scheduling strategy and ShedLock integration decisions
